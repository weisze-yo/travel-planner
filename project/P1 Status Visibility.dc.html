Two states, opposite meanings, both silent, distinguished today by hue alone at 8px on the most permanent chrome in the app. And they are not equally important: local is the state in which the whole sharing model is unavailable — no link can be created, no update can arrive, the trip dies with the phone. An unfilled dot differs by shape as well as hue, so it survives greyscale; it differs from the 10px animated ring by size, stroke and motion.
RC-14 / RC-15 — four wrong claims
The matrix says “five sync states in one 6px dot, no label, in a 44px chip”. Source: the dot is 8px and the ring is 10px; all five carry an aria-label; two of the five carry a visible sentence in .trip-meta.warn; and .trip-chip is flex: 1 sizing to two lines, not a 44px control.
Why the other two stay silent
A warning always names the tap that fixes it — and its contrapositive does most of the work here: where there is no tap, it is not a warning. saving is a ring that resolves in a moment. saved is the resting state of a working app, and a permanent “everything is fine” line is the definition of noise. sync.js's own header already says so: “then a solid green dot and no words. This is most of the time.”
Rejected, with reasons
A fifth colour — the palette has four semantics and grey is not one of them. A label under the dot — permanent, Map-only, duplicating the aria-label. A numeral in the dot — queued already has a sentence. A bigger dot — it sits over a live map and 8px is a deliberate quietness. Also rejected: wiring saving's computed line: 'Saving…' into the chip (P0-5 R3 — one animated vocabulary, and pending must never enter this chip).
The words that are warranted already exist
When the app is configured and still cannot reach the cloud, state.stranded is true and Map draws the rust .stranded card with strandedReason() — three branches, each naming its own cause. That is the case with a fix, and it has a sentence. The dot is not asked to carry it.

CANONICAL — FIVE SLOTS, ONE AT A TIME
1a loop reminder you will miss · red
2changes that cannot be sent · rust
3a loop reminder getting tight · amber
4outside a kept area · amber
5changes waiting for signal · amber
And it is the right order, which is why it is kept rather than renegotiated: 1 is time-bound and unrecoverable — a coach leaves whether or not the outbox drains. 2 is a standing risk to work already done. 3 is the same clock, further away. 4 and 5 are both “something is missing and the plan still works”. The identity marker yields to all five (P0-1 principle 5), and only the loop reminder is dismissible — returning when the walk gets 10 minutes longer.
X-7 — the queued strip has no action, and keeps it that way
Its body already says why: “Everything you have typed is already on the phone. This is only about the copy in the cloud, and it clears itself the moment signal returns.” There is no tap because there is no action, and the sentence spends its whole length saying so. A Try sending them now here would be a button whose honest label is “wait faster”. Recorded as a knowing exception with the rule it satisfies instead: a condition with no fix states that it needs none, in the same breath, and takes no action button. The second such exception in the product; the first is the read user's send block.

THE UNDO BAR — RECORDED, NOT REDESIGNED
Removed Skyline Deck
Undo
One app-wide bar in a global slot, six seconds, nine callers. Three states stated, none redesigned: a second deletion inside six seconds replaces the first (one bar, one label, the most recent thing — a stacked bar would make it a list); navigating away keeps it, because the six seconds belong to the deletion and not to the screen; and offline it is unchanged — the deletion is queued like any other edit and the undo queues the opposite.
One addition, and it is a rule
The label always names the thing, never the act alone. Written down because the bar is app-wide, it survives a screen change, and the next person to call rememberUndo has no document to check. A bar reading Deleted is unusable once you have left the list it came from. Existing labels obey it; so do P0-4's four.
The bar never covers the tab bar
.undo-slot is flex: none in the app column above #tabbar, so it pushes content up rather than overlaying it — which is why the slot has its own 0 12px 8px padding and bone background. Nothing is ever hidden behind it. Verified this session.
Net new CSS: one property
.sync-dot.grey becomes background: transparent with inset 0 0 0 1.5px var(--faint). syncDot() does not change — the class name still describes the state, not the colour. The blank-map card composes from .amber-note + .warn-fix.first, so it needs nothing new either.
Every string here is in §8
Two states' sentences are existing copy; the five aria-labels are unchanged; the strip's order is documentation, not copy. The only new strings on this board are the blank map's three lines.
The one area with no module state
Every state on this board is derived — syncState(), strip.js's one-minute tick, state.undo — so all of it survives a screen change and none of it can go stale. Recorded because it is the reason none of it needed a “navigating away” design.
