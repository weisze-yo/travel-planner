Eleven rules, in force order
R1
Pending renders on the control that started the work — label swap plus disabled. Never elsewhere on the screen.
R2
The label is the control's own verb in the present participle: Create → Creating…
R3
No spinner, ever.
R4
.amber-note is for outcomes and errors only.
R5
Work the user did not start gets no indicator — boot, the cross-tab refresh, the automatic forecast, the fire-and-forget publish.
R6
Real progress only when it measures something. Never an indeterminate bar.
R7
The disabled state is the double-tap prevention. No timers, no debouncing.
R8
Navigation during pending is allowed and pending state is disposable; the outcome surfaces where the result lives. Three flows keep their surface: Create, Join, the Paste save.
R9
Cancellation only where the work is long, measurable and resumable — the tile download, and nothing else.
R10
Synchronous work gets no pending state at all. The rule most likely to be "helpfully" broken later.
R11
A navigating action disables its family, without fading it.
B · Every control, in its pending state
Resting above, pending below. Nothing changes but the words and the opacity — the height, the type and the flex behaviour are identical, so nothing underneath moves.

NO PENDING STATE EXISTS HERE — DO NOT ADD ONE
Send n changes — publishUpdate() is synchronous and the network write is fire-and-forget. There is no interval in which a pending state could be true.
Read it — the parse is synchronous.
Keep mine / Take theirs — the writes are synchronous. Review gets the undo bar instead, per P0-4.
A label that flickers to "…" for one frame is worse than nothing, and it implies a network round trip that is not happening. There is also no minimum display time anywhere: if the work finishes before the next paint, the swap never renders.

C · Not designed, deliberately
a skeleton-screen family
a global loading overlay
a toast system

What this is instead: a convention — where the pending text goes, what it says, and what disables — plus the removal of pending text from a slot that should only hold outcomes. Per-call-site and mechanical. Zero CSS additions.
