Everything drawn here exists: the pencil is an .iconbtn.filled 40×40 r13 whose background goes --jade inline and whose glyph becomes icon.tick('#fff', 15); the gutter widens 56 → 60px and holds two .edge inputs (60px, pad 5·3, 11.5/700, tabular, r9) over the 10px/700 --faint derived length; .plan-name is 14.5px/650; .plan-remove is a 26px r9 --danger-bg ✕. Two additions only — the clause about ✕ in the hint, and the 11px line naming the accepted time formats. The warning strip is drawn in the approved fact-first structure (label · name line · fact line · fixes), which is a designed change: source labels this kind OVERLAPS and carries a single sentence. Its one fix is real and verbatim — dayIssues() offers exactly one for an overlap, Start 10:00 (act: 'retime', the running stop's end), and there is no second chip. Stop names, times and counts on this board are illustrative data; the strings are §10's.
RC-9 — a live stop cannot be swiped
The coverage matrix has “Delete a stop — swipe → latch → in-row confirm → undo”. swipeToDelete is bound to [data-plan-row], and stopRow() sets data-row-id. Only archive() sets data-plan-row, and only in edit mode. So that row describes stage 2 and attributes it to stage 1's control — and ✕ calls archivePlanItem, not delete.
RC-10 — the archive is not a P2 cosmetic
It is the reversible first stage of the app's best destructive model: ✕ → archive (row stays on screen, openable, with Add back on it) → swipe → in-row confirm → 6s undo for the irreversible one. Nothing collapses. It is also why the Plan needs no delete confirmation on a live row.
RC-11 — the vacated slot is not a decision
Lanes are derived from gaps between stops of at least 45 minutes. Remove the 14:00 stop and the gap becomes one dashed amber lane offering + Sub route here. “Close up” and “keep the gap as free time” are the same behaviour seen from either end. One consequence worth keeping: removing a stop adds a row in edit mode, and that row is where the freed time went.
RC-12 — the empty day is already tier 1
plan.js has its own emptyDay(): two .lane-stub dashes, a 15px/700 line, a 280px-capped teaching paragraph, one ink and one ghost action, a closing hint. That is the tier-1 treatment. parts.js's .empty twin belongs to the Map sheet. Frame 1B's sign-off is a confirmation, not a change.
The principle this screen adds
Edit mode is a mode, and everything destructive lives inside it. Outside the pencil, nothing on this screen can change or destroy anything — the ✕, the grips, the inputs, the chips, Add back, both swipes and both add buttons are all gated on state.editingPlan. Two consequences: no confirmation on entering or leaving (there is no dirty state), and the destructive ladder is two-stage by construction.

Today Add with nothing typed does nothing at all — one of four silent refusals in the app (New trip, add-a-stop, the item editor, the shot editor). The rule is canonical in p1-destination-tabs-design.md §6: the message goes in the field's own hint, in rust, and the button is never pre-disabled. Every string here is in §10
The markdown is canonical and this board illustrates it. Any string on this board that is not in p1-plan-editing-design.md §10 is a bug in the board, not a decision.
New CSS: none
.archive-moved already exists; .warn, .edge-derived, .amber-note and the rust field hint are all in use elsewhere. The two documented CSS additions for this screen belong to the approved warning strip (.warn-name, .warn-fact) and are not new here.
Three rejections, stated
Staged edits with a save step — the app commits on change everywhere. Arrow buttons for reordering — the alternative is named instead: a stop out of order is usually a stop with the wrong time, and the times are keyboard-reachable inputs. A confirmation on entering or leaving edit mode — there is no dirty state to protect.
