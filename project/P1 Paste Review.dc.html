THE STICKY FOOT · ANSWERS FOR MING
Save 7 stops is disabled while anything is genuinely unresolved, and enabled the moment nothing is. Unresolved means exactly three things: a line the parser could not read, a row where it guessed and nobody has answered, or a row that is invalid (§4). It is not gated on rows the parser read cleanly — that gate is what this design removes, so on a clean paste the button is live on arrival. The count beside it says what is holding it: 3 rows still need you → 7 stops ready.
"Is a row resolved automatically until there is no conflict?" — near enough, and here it is exactly. Every row arrives in one of three grades from the parser, and the grade decides the starting state. Nothing is ever resolved on your behalf that the parser had to guess at.

So the save unblocks when no row is left in ? or !. A dropped row (—) never blocks anything and never saves. You can also drop or restore an accepted row at any time by tapping its glyph — accepted is a starting state, not a lock.
More holds the two bulk actions, kept out of sight because in a well-graded list there is usually nothing to do in bulk: Drop the 3 rows that need me — the honest exit from a bad paste, which touches only the unresolved rows and never one the parser read — and Undo the drops. Dropped rows stay in the list, greyed, and go back with one tap. There is deliberately no Accept everything: the clean rows are already accepted, so the only thing it could do is answer the questions the screen exists to ask.

"WHAT HAPPENS IF I EXIT? WHY IS THIS PAGE NEEDED?"
The back arrow and Open the Plan do the same thing, and that is verified, not proposed — both run reset(); go('plan', {}, { replace: true }) in the source today. (The control is icon.back, not a close cross: paste.js 707 renders this screen through backHeader like every other push screen.) The stops are already saved either way. The write finished before this screen appeared; nothing here is a commit step and nothing is lost by leaving.
So it earns its place on one thing only: what it tells you that the Plan cannot. Two sentences — 2 stops have no position, so they are missing from the map until someone pastes a map link, and the pasted text is kept under Last import, which is the only undo this flow has. Neither is visible on the Plan, and both matter later.
Recommendation: keep it. A back arrow beside an identical primary is fine when the screen is a receipt — nothing here can be cancelled, and the title Saved says so before either control is read. If it were ever cut, the unplaced-stop count would have to move onto the Plan's warning strip first — otherwise the flow ends by silently hiding its one caveat.
