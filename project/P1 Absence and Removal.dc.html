Why this is the worst copy failure in the baseline
P0-1's product model is everyone edits their own copy, always. This screen told the one person whose confidence it costs the opposite — while the owner's own screen told the truth, and the kept list two centimetres below contradicted it. Recorded as X-1 in the consistency audit.

X-2 — two correct designs meeting badly
Under P0-4's retained base, emptying a joined copy leaves the base holding every stop while yours holds none. Every stop is then case 7 — “I removed it” — and case 7 never reaches the screen. The next update offers nothing, and the itinerary is unrecoverable by any route in the app. Resolution: emptying also clears reviewedSnapshot, which enters P0-4's already-approved no-base mode — every row offered, badged THEY SENT. No new state, no new mode, no new copy.
E · SHARE, NON-OWNER
Ana’s link has stopped working, so no more updates can arrive. Everything on this phone stays as it is.
Replaces the non-owner explainer's sentence (“Ana looks after who is on this trip and sends its updates”) while it applies — because that sentence is no longer true. Jade, not rust: nothing failed on this phone and nothing is lost. And nothing else changes — no banner, no chip, no strip. There is no tap that fixes it, so by the house rule it is not a warning; it is a fact, available where the question is asked. The condition is the last envelope read that got an answer, never a transient offline.
The confirm-button test
A confirm button is permitted only where both are true: the thing destroyed cannot be reconstructed by the user, and there is no row to swipe. Exactly two actions pass — discardPending and Empty this trip. Everything else in the app is swipe → in-row confirm → 6s undo. OD-6 asks the one question this design cannot answer for you: may this control delete the Log at all?
Every string here is in §9
The markdown is canonical and this board illustrates it. Any string on this board that is not in p1-absence-and-removal-design.md §9 is a bug in the board, not a decision.
