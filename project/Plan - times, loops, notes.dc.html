2Paste an itinerary · confirm it row by row
WHAT THE PHONE CAN ACTUALLY DO
It reads shapes, not meaning

With no server there is no language model in the loop — just pattern matching on the phone. It can find the shapes that itineraries are written in: a day header (Day 3, 14 Mar, Sat 14/3), a clock (09:15, 9.15am, 09:15–10:00), a bullet, an arrow. Everything after the clock it treats as a name and does not pretend to recognise.

So the review list has three grades, and the design is mostly about the second and third: found it — a jade tick and the time as written; worked it out — amber, and it says which part it inferred; could not read it — the raw line kept verbatim with three ways out. Nothing is written to the trip until the last screen.

EVERY ROW GETS A TAP

No bulk accept: this list is the one place where a wrong row is cheap to remove, so each one is ticked or dropped here. Review and save stays dead until none are outstanding — it opens the last look, 2e, which holds the only button that writes anything. The header says how many are left so you can stop and come back. After saving the trip is real — still editable, but editable one stop at a time.

WHAT IT NEVER GUESSES
Positions. A name in a PDF is not a place on a map. Imported stops arrive without coordinates and say so; you paste a map link later, per stop, when you care.
Sub routes. Free time is yours to declare. The import only ever creates main-route stops.
Deletions. Importing into a day that already has stops adds to it, and the last screen says exactly what will be added before you press it.
The pasted text is kept with the trip, so a bad import can be undone and re-read rather than retyped.

1Editable times · several sub routes a day · notes on a place
MY RECOMMENDATION
Two times, not a duration

A sub route's deadline is a clock time — 15:45 at the coach door. If a stop stores a start and a duration, that deadline becomes arithmetic you do in your head every time you change something, and the number you most need to protect is the one number never written down. So a stop holds starts and ends, both editable, and the duration is shown underneath as derived grey text.

1b is the duration version so you can judge it rather than take my word: it is one field lighter and reads well while you are typing, but the end time is then a value the app owns, which is exactly the thing you asked to be able to touch.

THE OTHER TWO RULES

Free time is a slot, not a stop. The gap between two stops is drawn as a dashed amber lane, and a sub route lives inside it. A day can hold as many lanes as it has gaps, so two or three sub routes never compete for one anchor. Each sub route is one card carrying its name and its own window.

A note belongs to a place and a time. The day still totals them, but it no longer owns them: the Log's day card groups the day's notes under the place they were written at, in the order you wrote them.

WHAT WARNS, NEVER REFUSES
The drag always lands. The row that is now wrong wears an amber strip naming what is wrong and the one tap that fixes it — out of order, overlaps, or ends before it starts.
A sub route whose stops no longer fit its window says so on the Plan card as well as inside the sub route, because you will be looking at the Plan when you drag.
Day-level count sits under the date, so you can leave the day messy on purpose and still know it is messy.
Nothing here needs signal: every check is arithmetic on times you typed.
